# Changelog

All notable changes to IASLib are recorded here. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and versions follow
[Semantic Versioning](https://semver.org/) from 2.5.0 on.

## [Unreleased]

### Added

- **SJSON** (`inc/SJSON`, `CSjson`): compact binary packets for JSON trees, a C++ port of the [Python sjson library](https://github.com/jnaujok/sjson) and wire-compatible with it (identical bytes for the same document; packets decode in either).
  - Dictionary compression of field names with a NAK exchange, tight number encodings (integers of any size, float32 when exact, float64, decimal digits) and string forms (UUID, interned, LZ4, range coding, hex, ISO-8601, base64).
  - Schemas: JSON Schema (drafts 4 to 2020-12, `$ref` across files) and XSD loaders, Python-identical fingerprints, compiled dictionary files, and the schema-driven encoding that drops field tags and type codes.
  - Stream mode: per-field recent-value caches, float / integer / timestamp / prefix deltas, inline name definitions, sequence numbers with gap detection and reset, and a zstd text channel.
  - `TestSjson` checks byte-for-byte agreement with the Python library; `BenchSjson` measures both on the same message streams.
  - New option `USE_SJSON` (default `ON`); LZ4 (liblz4) and zstd (libzstd) are optional dependencies.

## [3.0.0] — 2026-11-18

Every folder of the library reviewed and brought up to date. The base types and collections were cleaned up, and every collection got a template version. The stubs are filled in: the memory manager, a resource archive and manager, memory-mapped files, an HTTP client, SMTP mail, and the SQLite driver's updatable cursors. Sockets support IPv6. Every public class, method and field has Doxygen documentation, and the build publishes it as HTML and PDF.

### ⚠️ Breaking changes

- **`CCString` (`String_Copy.h`) is removed.** It was unused, and `IASLIB_USE_DEEP_COPY_STRING__` could not have worked (it named a different class). `CString` copies are now safe across threads.
- **`IASLibChar__` is `char` on every platform.** It was `TCHAR` on Windows, which the string code never handled as wide characters.
- **`CString` details:**
  - Doubles and floats become the shortest text that reads back as the same value (`"0.1"`, `"2"`), always with a `.` decimal point; they were `"%f"` (`"2.000000"`) in the C locale's format.
  - `Replace()` and `Remove()` with strings make one pass, so text put in is not searched again.
  - `Escape()` also escapes `+`, so `Unescape()` gives back the original.
  - The `const` `operator []` returns a character, not a reference.
  - `getBytes()` returns `const unsigned char *`.
  - `hashcode()` is `hashCode()` (the old name still works) and overrides `CObject`'s, so equal strings hash alike everywhere.
  - Stream input (`IASLIB_STD_STREAM_SUPPORT__`) reads a word, as `std::string` does.
  - `dumpStubMemory()` is gone.
- **`CObject`:**
  - `GetType()` and `IsType()` are `const`.
  - `SetAssertHandler()` takes the handler to use.
  - A copied object gets a new ID.
  - `Object.h` no longer includes the threading headers.
- **Collections:**
  - Collections that own `CObject` pointers (`CArray`, `CHash`, `CList`, `CQueue`, `CSparseArray`, `CCache`) can't be copied. Every copy used to free the same objects twice.
  - `CSparseArray` is no longer a `CSortedArray`.
  - `CHash` keeps entries in the order they were added, and number keys equal their digits as strings.
  - `CQueue` iterates from the front.
  - `CCollection::m_nElements` is gone; `GetLength()` is virtual.
  - `CSortedArray::Find()` returns `NOT_FOUND` instead of an encoded insertion point.
  - `CCacheItem`'s list links are gone.
  - `HashBucket.h`, `HashSlat.h` and the unfinished template drafts (`TCollection.h`, `TEntry.h`, `TIterator.h`, `TMap.h`, `TDoubleList.h`, the old `TCache.h`) are removed.
- **`CUUID`:**
  - 16 bytes, written in the standard 36-character form.
  - `getBytes()` and `toString()` are `const`.
  - It no longer uses `TRandom`.
- **`CStringTokenizer`:** with every delimiter counting, `"a,"` gives `"a"` and `""` (n delimiters, n + 1 tokens).
- **XML:**
  - Reading and writing are rewritten, keeping the classes and their methods.
  - Entities and character references are now decoded on reading, and text and attribute values are escaped on writing (they were read and written as typed).
  - Documents that aren't well formed are rejected with a line and column. That includes `\` escapes in attribute values, which XML doesn't have, and repeated attributes.
  - Line breaks read as `"\n"`.
  - Pretty-printed output no longer adds blank lines, and starts each top-level element on its own line.
  - `CXMLData::GetData()` returns a `const CString &`.
  - `CXMLElement( CString & )`, which parsed the start of a string, is removed.
  - CXMLDocument and CXMLIndex can't be copied.
- **`CMutex` can't be copied.** Copying one copied the operating system's mutex.
- **Threads:**
  - The thread monitor deletes only detached threads when they finish (joinable threads belong to whoever made them; it used to delete them too, 30 seconds after they ended).
  - `Sleep()` and `Millisleep()` are static.
  - The public `m_mutexStartSuspended` is gone.
  - `CThreadPool` keeps its threads in `TArray`s and takes `CThreadTask`s only.
  - `CServerThread` checks for shutdown every 250 ms.
- **Streams:**
  - `>>` reads numbers and strings as text, the way `<<` writes them. It used to read big-endian binary, so nothing written could be read back. Binary reads and writes are now explicit, as `PutUInt16()`, `GetUInt32()` and the rest.
  - `PutLine()` ends the line on every stream.
  - `GetLine()` leaves off `"\r"`.
  - Reading past the end throws a CStreamException on every stream (file and null streams used to return `'\0'`).
  - CStringStream holds bytes (`GetOutput()`), NULs included.
  - Destroying a CBufferedStream flushes it but no longer closes the stream underneath.
  - `bytesRemaining()` is `NOT_FOUND` where a stream cannot tell.
  - The `BUFFER_SIZE` macro is now `CBufferedStream::BUFFER_SIZE`.
- **`CMutex` is recursive on every platform.** The thread that holds it can lock it again, and must unlock it as many times. It was recursive on Windows (a kernel mutex) but not elsewhere, so code that worked on Windows deadlocked on Linux and macOS. On Windows it is now a critical section, which avoids a kernel call when the lock is free.

- **Sockets:**
  - `NULL_SOCKET` is `INVALID_SOCKET` (-1 outside Windows). It was 0, which is a real descriptor.
  - Socket errors are thrown by value, as `CSocketException`, and `GetErrorNumber()` is an errno value on every platform (Winsock's WSAE* codes are translated). `CSocket::Read()` and `CServerSocket::Accept()` used to throw pointers, so `catch ( CSocketException & )` missed them.
  - `CSocket::Read( void )` and `Send()` throw on an error or a closed connection. `Send( unsigned char )` used to return 0.
  - On a client socket, `GetPort()` and `GetAddress()` are the far end's. They held the near end's; use `GetLocalPort()` and `GetAddressString( false )` for that.
  - The `CSocketConfigBuilder` setters return a reference, so a chain keeps every setting (the copies they returned lost all but the first). `Build()` returns a `CSocketConfig` by value. `CSocketConfig` has a public constructor; it defaults to blocking with no timeout.
  - Servers given no address (`CServerSocket( port )`, `CUDPSocket( port )`, and so the SIP and HTTP servers) listen on IPv6 and IPv4 at once, falling back to IPv4 alone on a machine without IPv6. Pass `"0.0.0.0"` for IPv4 only. An IPv4 peer of such a socket is reported as plain IPv4, not `::ffff:a.b.c.d`.
  - CUDPSocket no longer sets `SO_REUSEADDR`, which let a second socket bind the same port.
  - `CRemoteAddress` is a typedef of `CInternetAddress`. It was an unused copy of it.
  - `FixedConnectionPool.h` and `ClientSocketSource.h` were never implemented, and are removed.
- **Stats:** the Stats classes are always built. They were inside `IASLIB_STATS__`, which the CMake build never defined, so the library shipped them empty. Histogram counts are `long long`.
- **`CCPUUsage`:** the elapsed-time methods take a `const CCPUUsage &`.

- **Logging:**
  - The `*_LOG` macros are single statements (`do { } while ( 0 )`) that read the sink once and skip formatting below its level. They were bare `if` statements that captured a following `else`, and read the sink twice.
  - Destroying a sink clears the default only if it is the default (destroying any sink cleared it). Sinks take a `bMakeDefault` argument; `setInstance()` sets the default.
  - `CLogFile` and `CRotatingLogFile` take an auto-flush argument; lines at ERROR and above are always flushed. A file that cannot be opened leaves the log closed instead of throwing.
  - `CRotatingLogFile` deletes all but the newest `nFilesToKeep` files that match its template. It used to keep everything.
  - `CLogContext::getArrayValue()` returns NULL for a missing name, not a shared empty array.
- **Files:**
  - `CFile` cannot be copied: a copy shared the `FILE` and closed it twice.
  - `CFile::Rename()` replaces an existing file on Windows too.
  - `CDirectory` lists entries sorted by name, and a directory that cannot be read gives an empty list.
  - `CDirectoryEntry::m_lSize` and the CFileStat size are 64-bit.
  - The `CRWFile` index is written in binary mode, so its records are 16 bytes on Windows too.
- **Files:** `CFile::GetPos()`, `GetSize()` and `Seek()` return -1 when the value does not fit in a `long` (past 2 GB where it is 32 bits, as on Windows). They used to return a wrong value. A failed `Seek()` returns -1 rather than the old position, and seeking past the end no longer changes the size `GetSize()` reports.
- **Resources:** `CResource::Load()` and `Save()` take the `CResourceFile` to use (they were declared without one and never defined). The compression constants are in `ResourceIndex.h`.
- **Database:**
  - The SQLite driver uses SQLite directly (it went through `CDynamicLibrary`) with prepared statements. `Execute()` and `Cursor()` take bound parameters; a cursor takes one statement that returns rows.
  - Transactions are real `BEGIN`/`COMMIT`/`ROLLBACK` (they were emulated by buffering the SQL text). A failed commit rolls back.
  - `CSQLiteDatabase::Connection()` returns NULL when the database cannot be opened, with the error on the database. `SetTimeout()` returns true.
  - `CDataTable`, `CDataIndex` and `CDataField` refuse names from a definition that are not SQL names (they went into the SQL as written). `CreateTable()` returns the commit's result and skips blank `<initialize>` lines; `DropIndex()` writes `drop index name` except on Sybase. The undefined `LoadTable()` and `LoadIndex()` declarations are removed.
  - Oracle cursors quote values with quotes doubled, return `IASLIB_DB_OK` on success (they returned the `bool`), and their `InsertRow()` writes the `(` it was missing. Arrays in the Oracle and Sybase drivers are freed with `delete []`.
  - `CBaseResult::Next()` stops at the last row (it kept counting), and column names match without regard to case.
- **Configuration:**
  - `CProfile` is rewritten with the same interface. It no longer throws for a missing file (it reads as empty and the first write creates it). Every write saves at once through a temporary file, keeping comments, blank lines and order; without the cache, reads see changes made by others. The `const char *` `GetString()` stays valid (it pointed into storage a later call could free); the buffer form always ends its text; `GetInt()` gives the default for text that is not a number.
  - `CSettings::ReadSettings()` returns false for a missing file (it threw), keeps `=` inside values, skips indented comments and `;` comments, and a later line replaces an earlier one.
- **DynamicLibraries:** `CDynamicLibrary` uses a name with a directory or extension as given, and tries a bare name in the platform's form (`libfoo.so`, `libfoo.dylib`, `foo.dll`) and then as given (it always used `lib%s.so`, on macOS too). A library that fails to load is safe to use: `GetFunction()` throws, where dlclose(NULL) crashed and dlsym(NULL) searched the program itself. It cannot be copied.
- **Encryption:** `CSHA256` is ready to use when constructed, and `final()` starts it over. `Encrypt.h` is marked as declarations only (it never had an implementation).
- **Exceptions:**
  - Every exception class overrides `Rethrow()`, so `IASLIB_RETHROW` keeps the class (it threw a plain `CException`).
  - `CException::ErrnoToText()` gives the system's text (a fixed table from one Unix was wrong elsewhere). `CFileException` uses it for numbers it has no message for.
  - `CWindowsSystemException` puts the system's text in the exception's message, and copes with `FormatMessage()` failing.
- **JSON:**
  - `JsonNodeType` values have a `JSON_` prefix (`JSON_ARRAY`, `JSON_BINARY`, `JSON_BOOLEAN`, `JSON_MISSING`, `JSON_NULL` (was `NULLVAL`), `JSON_NUMBER`, `JSON_OBJECT`, `JSON_STRING`): the bare names clashed with the Windows headers. Outside Windows the old names stay as aliases unless `IASLIB_JSON_NO_LEGACY_NAMES__` is defined.
  - `CJsonNode::path()`, `at()` and `findPath()` return `const CJsonNode &`, and `CMissingNode::getInstance()` a `const` reference, so the shared missing node cannot be changed through them. Use `get()` (NULL when absent) to change a node.
  - Integers from 2^63 to 2^64-1 are `isUnsignedLong()`; `isBigInteger()` now means too large for 64 bits.
  - Arrays and objects store a missing node they are given as a JSON null.
  - `CCollectiveNode` has a pure virtual `detachChildren()`; `CJsonNode::collect()` is no longer virtual.
- **Blockchain:** difficulty is capped at `MAX_DIFFICULTY` (64): `CBlock::mine()` returns false above it, `setDifficulty()` and the constructor clamp to it, and `FromJson()` and `Deserialize()` refuse a higher one. (256 could never be mined.)
- **NetworkServices:**
  - `CGenericClient` no longer derives from `CClientSocket` or connects in its constructor: it holds the host, port and secure flag, and clients open their own connections (`CHttpClient` on its first request).
  - Setters that take header names, values, URIs, methods or mail addresses return `bool` (false: refused, nothing changed) instead of `void`: `CHeader::setValue`/`addValue`, `CHeaderList::addHeader`/`appendHeader`, `CGenericRequest::setRequestType`/`setUri`/`setVersion`/`setHeaderValue`/`setHeaderValues`, `CGenericResponse::addHeader`/`addHeaders`, `CMail::From`/`AddRecipient`/`Subject`. Overrides need updating.
  - `CGenericRequest` and `CGenericResponse` (and so every HTTP and SIP message) cannot be copied: a copy deleted their pointers twice.
  - `CHttpClient::executeRequest()` returns NULL on failure, with the reason in `getLastError()`.
  - `CMail`'s default server is `localhost` (was `pop.mail.com`); a sender or recipient that is not a plain mailbox is refused, and a refused recipient stops the send.
  - `CGenericRequest::parse()` fails on a header section with no blank line at its end; header lines whose names are not tokens are skipped as malformed.
- **Threading:** on Windows, `CThread::Kill()` ends the thread at its next sleep or semaphore wait (an APC) instead of `TerminateThread()`, which could stop it holding the heap lock and hang the process. It returns -1 if the thread has not reached one within two seconds.
- **Memory manager:** with `IASLIB_MEMORY_MANAGER__` or `IASLIB_MEMORY_DEBUGGING__`, CObject classes are allocated through `CMemoryManager`. The fencepost allocator is now `CMemoryDebugHeap`, which reports one line per damaged fence (it printed one per byte) and reports through `CMemoryManager::SetErrorHandler()`. The memory manager also applies without RTTI.

- **Resource manager**, for games and other programs with many resources to load (it was an empty skeleton):
  - `CResourceManager` loads resources by path (`"textures/hero.png"`) and keeps them while they are wanted.
    - Sources are searched in priority order, so loose files or a patch can override the main archive: `CArchiveSource` (an archive, by resource name) and `CDirectorySource` (loose files). Programs can add their own.
    - Loaders registered by file extension turn bytes into typed resources (subclasses of `CLoadedResource`); `Get<T>()` returns the type. Without a loader a resource is a `CRawResource` holding its bytes.
    - Handles are shared: every request for a path gets the same object, which lives while anyone holds it.
    - Over its memory budget, the manager unloads the least recently used resources that nobody else holds, never one in use.
    - `LoadAsync()` loads on worker threads, and callbacks run on the thread that calls `ProcessCompleted()`, such as a game's main loop. Requests for a path already loading share that load, and so does a `Get()`, which waits for it.
    - Also `Unload()`, `UnloadUnused()`, `Reload()` (holders of the old object keep it), `Exists()`, `WaitForPending()` and statistics.
  - `CResourceFile`, the packed archive:
    - Resources by folder and resource tags or by name.
    - SHA-256 digests on the data and the index. A crash part-way through a write leaves the archive as it was at the last `Flush()`.
    - `Compact()` reclaims space from replaced or removed resources.
    - A `TCache` with a byte limit, which `CArchiveSource` turns off because the manager caches.
    - 64-bit offsets throughout, so an archive can be any size.
  - `CResource` is a resource in an archive, with its name, type, and when and by whom it was changed. `CResourceDirectoryNode` and `CResourceFileNode` give a folder view.
  - `TestResources` and `TestResourceManager`.

### Fixed

- **`CString`:**
  - **Memory errors:**
    - Shortening a string to nothing wrote to freed memory.
    - `ToHex()` wrote past its buffer.
    - `hashcode()` crashed on an empty string.
    - Fixed-buffer strings could overrun their buffer, and appended text past the length they recorded.
  - **Wrong results:**
    - `"abc" == str` compared pointers.
    - `"" < "a"` was false.
    - `operator []` changed every copy of a string.
    - `Remove( char )` kept the old length.
    - `Replace()` looped forever when the new text contained the old, or the old was empty.
    - `LastIndexOf()` never found a match at 0.
    - `"abc"` didn't match the wildcard `"abc*"`.
    - `Copy()` did nothing on an empty string.
    - `Unescape()` read past the end, and turned bad escapes into NULs.
  - **Limits:**
    - `Format()` cut text off at 64 KB, through a shared buffer.
    - Every string had its own mutex.
    - Appending a character at a time copied the whole string each time.
  - **Missing:** `hasDelimitedTokens()` was declared but never defined.
- **`CObject`:**
  - Object IDs were counted without a lock, unless the build was multi-threaded.
  - The memory-debugging allocator crashed on a failed allocation or a NULL delete.
  - `ASSERT` broke `if`/`else`.
- **Templates and memory debugging:** classes built with memory debugging hid placement `new`.
- **`CDataBlock`** never recorded its size, so the first guardpost check read far outside the buffer. It also wrote the back guardpost inside the data, freed `malloc` memory with `delete`, and could throw from its destructor.
- **`CUUID`:**
  - It held 32 bytes and printed a form of varying length.
  - It couldn't parse a UUID (`*uuid + 1`).
  - It was seeded from the clock, so two programs started in the same second made the same UUIDs.
- **`TRandom` (ISAAC):**
  - The default integer type was 64 bits on Linux and macOS.
  - Seeding without a seed filled only 8 of its 256 words.
  - ISAAC-64 mixed with the 32-bit form.
  - Copies freed the same tables twice.
  - `UINT32` clashed with Windows' own type.
- **`CVariant`:**
  - The default constructor left every member unset.
  - `v = "text"` stored the boolean `true`.
  - NULL arrays and objects crashed `getString()`.
  - `getInt()` gave 0 for `long` values.
- **`CStringTokenizer`:** a one-character string gave no tokens in every-delimiter mode, and trailing empty tokens were dropped.
- **`CArray`:**
  - `Set()` past the end wrote past the buffer.
  - Copying or assigning an array freed its objects twice.
  - `Sort()` of an empty array read out of bounds.
  - It grew four slots at a time and shrank on almost every `Remove()`.
- **`CSortedArray`** never sorted. `Push()` appended at the end, or dropped (and leaked) a value equal to one already there.
- **`CSparseArray`** inherited that.
- **`CHash`:**
  - `Delete()` removed every key in the same bucket.
  - `Remove()` lost count.
  - Negative number keys indexed outside the table.
  - The string hash ignored the last character.
  - A key with surrounding spaces could be dropped and leaked by `Push()`.
  - Copies and assignment freed buckets twice.
  - Iterating rescanned the table for every element.
- **`CCache`:**
  - `ClearExpired()` read the item it had just freed.
  - Adding a key twice left a deleted item on the LRU list.
  - A one-entry cache crashed when it evicted.
- **Other collections:**
  - `CQueue::Pop()` moved every element.
  - `CStringArray::EmptyAll()` leaked every string.
  - `CIntArray` and `CStringArray` copies freed twice, and their sorts crashed when empty.
  - `CConnectionArray` freed memory with the wrong `delete`.
- **Copies that freed twice:** `CLogContext::addValue( CArray & )` and the thread pool's shutdown each copied an owning array.
- **`CStream << unsigned long`** wrote `"123ld"`. `printf` checking also found `size_t`s printed with `%d`.
- **XML:**
  - `&amp;`, `&lt;` and character references were never decoded, and nothing was escaped on output, so `<` or `&` in data produced XML that couldn't be read back.
  - `</a >` (a space before `>`) was reported as mismatched.
  - `<!--x-->` comments without a space weren't recognised.
  - `DeleteProperty()` and `DeleteSubElement()` were declared but never defined, and `CXMLParser` had no implementation.
  - A parse error leaked the partly built tree.
  - `CXMLIndex( file )` used a second, string-searching parser that misread nested elements of the same name.
  - Pretty printing put an element on the same line as a self-closing one before it.
  - `TestXMLDocument` checked with `ASSERT`, which only prints, so it could never fail.
- **Threads:**
  - Starting a suspended thread was a mutex locked by one thread and unlocked by another, which mutexes don't allow. Resuming from another thread failed with the recursive mutex. It's now a condition variable.
  - `Join()` skipped threads that had already finished, so they were never joined and leaked. `CGenericServer` had worked around this.
  - On Windows, `Self()` and `Equals()` compared `GetCurrentThread()`, which is the same pseudo handle in every thread. `ExitThread()` called itself forever.
  - `ExitThread()` and `Kill()` aborted the program on Linux, because the `catch ( ... )` around `Run()` swallowed the stack unwinding they use.
  - A thread destroyed before it started could still run.
  - The monitor's singleton could be created twice, and its shutdown list deleted threads twice.
  - **CThreadPool:**
    - Its workers waited on a mutex unlocked by another thread. With the recursive mutex they spun instead, and on Windows they had never worked.
    - A task that threw a library exception killed its worker for good.
    - `TaskStatus()` always said UNKNOWN.
    - Destroying the pool left threads running on freed memory and leaked them.
  - **CServerThread** waited in `Accept()` forever, so it couldn't be stopped, and caught exceptions by pointer, which never matched.
  - `CFileStream::GetBuffer()` looped forever on Windows text files.
- **Streams:**
  - `<< unsigned short` wrote `"%ud"` (`5` became `"5d"`).
  - `>> CString` trusted a length read from the stream and freed with the wrong `delete`.
  - `<< (const char *)NULL` crashed.
  - CBufferedStream:
    - Characters written with `PutChar()` were lost on close.
    - `GetBuffer()` dropped the last buffered bytes once the stream underneath ended.
  - CSocketStream:
    - `IsEOS()` was inverted (true when data was waiting).
    - Reads looped forever when the peer closed, and counted errors as -1 bytes.
    - A second `PeekChar()` took the character.
  - CFileStream:
    - `PeekChar()` seeked with `SEEK_SET`, which isn't one of CFile's modes.
    - Writes looped forever on an error.
  - `CSocket::HasData()` called `select()` with a descriptor count of 1, so outside Windows it only ever looked at descriptor 0.
- **Sockets:**
  - `CSocket`:
    - Clients looked hosts up with `gethostbyname()`, which isn't thread-safe, and copied 8 bytes out of a 4-byte address. `socket()` was never checked.
    - The configured options were applied wrongly or not at all:
      - The timeouts were passed as an int, which POSIX systems reject (they take a timeval).
      - `SO_LINGER` was passed an int rather than a `struct linger`.
      - Keep-alive was never applied.
      - The buffer sizes were set after connecting.
    - On Windows:
      - `Send()` resent from the start of the buffer and counted a partial send as complete.
      - `SetNonBlocking()` did nothing.
      - Errors were taken from errno.
    - Binding with a configuration bound IPv4 only, whatever the address.
    - `GetAddressString()` overwrote the stored address, so the next call returned the wrong text.
    - Address text came from `inet_ntoa()`, which shares one buffer between threads.
    - Winsock was started behind an unguarded flag in every constructor.
    - `m_bBlocking` was never initialised.
    - `getInternetAddress()` returned one static object that every socket shared and could change.
  - `CServerSocket`:
    - `listen()` was never checked.
    - The destructor set an option on a socket it was about to close.
  - `CUDPSocket`:
    - The client constructor read its address with a length of 0, so its port was garbage.
    - `Close()` left the handle set, so the destructor closed it again.
  - `CInternetAddress`:
    - A numeric service, or any datagram lookup, dropped the port.
    - The sockaddr constructors went through text and a `SOCK_RAW` lookup, which Linux refuses with a port.
    - `SetAddress( hostname )` lost the port and left the validity flag as it was.
    - `addressToString()` and `lookupHost()` crashed on NULL, and `lookupHost()` could return an uninitialised buffer.
    - IPv6 addresses with a port are written in brackets.
  - `CSafeAddressInfo` copied `ai_addrlen` bytes into a fixed-size address and deleted it as the wrong type. It now holds a `sockaddr_storage`.
  - `CSocketConfig` left every field uninitialised.
  - `CSocketException`'s unknown-error message is formatted properly, and covers the connection errors.
  - Mail and the thread monitor caught exceptions by pointer, so those catches never ran.
- **Logging:**
  - `CRotatingLogFile`:
    - It read its file pointer before setting it.
    - It checked for rotation outside the lock that guarded the file, so two threads could rotate at once, or write to a file another had just deleted.
    - `setAutoFlush()` did nothing.
    - Weekly and monthly rotation could stall.
  - `CLogFile` leaked its file, and reported success when a write failed.
  - Log messages were cut at 4096 bytes.
  - On Windows, the source file kept its whole path.
  - `CConsoleLog` did not flush its output.
- **Files:**
  - `CFile`:
    - `GetLine()` shared one static buffer between every file and thread, refused binary files, and seeked backwards in text mode to handle long lines.
    - `IsEOF()` was always true past 2 GB.
    - Reopening in another mode kept the old mode's flags.
    - A file opened with no mode lost `BINARY`.
    - `Close()` and `Flush()` ignored errors.
  - `CFileStat`:
    - Sockets and block devices counted as directories (the type was tested with `mode & S_IFDIR`).
    - Sizes past 2 GB were wrong on Windows.
    - It took a needless global lock, and trimmed spaces from names.
  - `CDirectory`:
    - A directory that could not be opened crashed it.
    - On Windows the TCHAR calls broke UNICODE builds, and a buffer was freed with the wrong `delete`.
    - Lightweight listings were ignored except on Windows.
  - `CDirectoryEntry` left its size unset when the entry could not be read.
  - `CRWFile`:
    - Failing to open a file threw instead of trying to create it.
    - On Windows the reader wrote its position over the writer's.
    - Reopening a finished file for writing wrote over it from the start.
    - A reader could take half of a line still being written.
    - A written line containing newlines counted as one.
- **Files:** on Windows, `CFile` opened files with `fopen_s()`, which nothing else can open at the same time, so a log could not be read while it was being written. It opens them shared, as on other systems.
- **Memory manager:** `MemoryManager.h` defined `new` as a macro for every file that included it, defined an inline replacement `operator delete`, and declared an allocator pointer that was never defined, so `USE_MEMORY_MANAGER` did not compile.
- **Stats:**
  - `CHistogram`:
    - The CSV header was one column to the left of the data.
    - Numbered categories without names gave ragged rows.
    - Bucket numbers above `INT_MAX` printed negative, and counts could overflow.
    - Names went into the CSV and XML unescaped.
  - `CCoverageMap` never worked: blocks were compared by pointer, so `Allocate()` never merged, `Release()` never released, the counters stayed 0, and `Dump()` wrote no data (and malformed XML). It is now a merged interval map.
- **`CCPUUsage`:**
  - Outside Windows, the total's microseconds were never carried and could reach 1,999,998.
  - On Windows, exactly 1,000,000 was not carried.
  - Failed calls left the fields undefined.
- **Exceptions:** every exception printed `"CException::FileLine - ..."` to stdout when thrown.
- **Security:** external entities (XXE) are refused, and entity expansion ("billion laughs") is capped.
- **Exceptions:**
  - The `IASLIB_THROW_*` macros threw a shared `static` exception, which two threads could change at once.
  - JSON: deep trees no longer overflow the stack. The parser keeps its own stack, and writing, cloning, `equals()`, finding and destruction walk the tree without recursion, so a raised `setMaxDepth()` works (100,000 levels are tested); the default of 512 still rejects deeper input cleanly.
  - JSON: the writer emits `null` for a missing child (it wrote `[,1]` and `{"a":}`). Removing a field shifts only the fields after it (the whole name index was rebuilt). Integers from 2^63 to 2^64-1 are exact (they were doubles), so Blockchain nonces round-trip across the full 64-bit range.
  - `CMail` checks every SMTP reply (multi-line too), sends EHLO (then HELO), connects through `CClientSocket` (IPv6, no leaked sockets), refuses CR/LF/NUL in addresses and the subject, keeps blank lines, sends CRLF line endings with dot-stuffing and no stray blank line before the final ".", and adds Date, Message-ID, MIME-Version and Content-Type headers (an RFC 2047 subject when not ASCII; BODY=8BITMIME when offered).
  - CR, LF and NUL are refused in HTTP and SIP header names and values, URIs, methods, versions and reason phrases; a lone CR in a header section gets a 400.
  - `serialize()` adds no Content-Length when Transfer-Encoding is set (and removes one). An empty POST or PUT sends `Content-Length: 0`.
  - `CGenericRequest::parse()` handles streams of unknown length (it asked for a buffer of (size_t)-1 + 1 bytes), reads bodies in pieces until complete, and keeps zero bytes; `CEntity::getEntity()` too. Bodies with zero bytes were cut short in `CHttpListener` (giving a 400) and in `CBasicSipServer`.
  - `CGenericServer`'s flags are atomic, and concurrent `Wait()` calls return only once the thread has finished. `HttpHeader.cpp` has its `IASLIB_NETWORKING__` guard.
  - `CCollectionException` named itself `"CCollectionExcetption"`, and `CXMLException` `"CXMLExcetption"`.
  - `CStringException` registered `CObject` as its parent class; its and `CXMLException`'s number constructors left "Unknown Exception" on the call stack.
  - `CFileException`'s `EOVERFLOW` message was behind a misspelt `IASLIB_SUN_` and never compiled.

### Build and CI

- **CMake:**
  - The version is 3.0.0, and `IASLibConfig.h` gains `IASLib_VERSION_PATCH` and `IASLib_VERSION_STRING`.
  - The `IASLib` target carries its include directories and feature macros as PUBLIC usage requirements, so a project using `add_subdirectory()` or `FetchContent` gets them by linking to it.
  - The tests are built only when IASLib is the top-level project (`IASLIB_BUILD_TESTS`).
  - `cmake --install` installs the library, its headers (`include/IASLib`) and a CMake package, so `find_package( IASLib 3.0 )` gives `IASLib::IASLib`, with the include directories, feature macros and dependencies the library was built with. `IASLib::IASLib` is also an alias in a build tree.
  - CPack builds `.deb` (`libiaslib-dev`), `.rpm` (`iaslib-devel`) and `.tar.gz` packages. CI builds them, installs the `.deb` and builds a `find_package` consumer against it, and releases attach them.
- **Documentation:**
  - A `Doxyfile` documents every public header, with `docs/Architecture.md` (mermaid diagrams) as an extra page.
  - The *Documentation* workflow builds the HTML site and a PDF on every push and publishes them as the `IASLib-documentation` artifact (HTML zip, PDF and the warnings log). Releases attach both.
- **The handler macros** (`IASLIB_SET_SIP_HANDLER`, `IASLIB_DEFINE_HTTP_HANDLER`) work outside `namespace IASLib`.

## [2.5.0] — 2026-11-17

A large update: the library now builds and passes its tests on Linux (GCC and Clang), macOS and Windows (MSVC) from the same source, and gains named time zones, a complete JSON library, TLS, and a rebuilt blockchain.

### ⚠️ Breaking changes

- **Legacy HTTP classes removed.** `CHTTPClient`, `CHTTPHeader`, `CHTTPHeaderList`, `CHTTPResponse`, `CHTTPServer` and `CServer` (the `NetworkServices/HTTP*.h` files) were replaced by the classes in `NetworkServices/HTTP/`. On case-insensitive file systems (macOS, Windows) their headers hid the new ones. They remain in git history.
- **`CHash::HUGE` is now `CHash::ENORMOUS`.** Apple's `math.h` defines `HUGE` as a macro. Stored hashes still use the text `"HUGE"`.
- **Blockchain difficulty is in leading zero bits**, no longer in hexadecimal zeros: the old `6` is `24` now. The default is 16.
- **Blockchain hashes and formats changed entirely.** Blocks hash a fixed binary header and hold binary entries. Chains made with the old code can't be verified by the new code.
- **`CBlock::getHash()` returns a binary digest.** Use `getHashString()` for hexadecimal text.
- **`MerkleNode` removed**, replaced by `CMerkleTree`. It never compiled, so nothing could have depended on it.
- **JSON API.** `longValue()` and `asLong()` return `long long`, since `long` is 32 bits on Windows. `binaryValue()` fills a byte vector instead of returning `char *`. The find methods return `std::vector`. `CPojoNode` and `CJsonDocument` are removed.
- **Windows builds target Windows 10** (`_WIN32_WINNT 0x0A00`) unless a program sets its own target. The previous target, Windows 2000, was too old for the socket code. `windows.h` is now included lean, without the `min`/`max` macros or GDI.

### Added

- **Named time zones** (`CTimeZone`):
  - IANA zones such as `America/New_York`, read from the system's zone database, with the full history and the rules for future years.
  - On Windows, zones come from Windows' own ICU library (`icu.dll`).
  - The system zone is read from `$TZ` or `/etc/localtime` with the same code, so it behaves identically on every platform.
- **`CDate`:**
  - ISO 8601 formatting and parsing.
  - Julian Day conversions.
  - A UTC offset stored with each date, with conversions between zones (`ToTimeZone`, `ToUTC`, `ToLocalTime`, `AssumeTimeZone`).
  - `SetDefaultTimezone()` for dates without a zone. They follow the system's zone by default.
  - An optional Herschel 4000-year rule (`USE_HERSCHEL_CORRECTION`).
- **JSON library** (RFC 8259):
  - A strict parser with line and column errors, options for comments, trailing commas and duplicate keys, and a nesting limit.
  - A Jackson-style node tree with `path()` chains, JSON Pointer, find methods, deep equality and copying.
  - Compact, pretty and ASCII-only output, with shortest-exact doubles regardless of locale.
  - `JSON` is now built by default.
- **SIP server** (RFC 3261):
  - A rebuilt protocol core with server transactions and their timers, CANCEL, the RFC 6026 accepted state, `received`/`rport`, CRLF keep-alives and compact headers.
  - `CBasicSipServer`, a working server over UDP and TCP.
  - The base class's `Run()` stays a stub for derived servers.
- **HTTP/1.1 server** (RFC 9110/9112):
  - A protocol core with keep-alive and pipelining, chunked bodies, `100-continue`, and request-smuggling defences.
  - `CBasicHttpServer`.
- **Secure sockets** (OpenSSL):
  - `CTlsContext`: certificates and keys from files or PEM text, TLS 1.2+, and verification of certificates and host names.
  - A working `CSecureSocket` for both clients and servers, safe for one thread to read while another writes, and free of SIGPIPE.
  - HTTPS (`CBasicHttpServer::setTlsContext`), and SIP over TLS on its own port (`CBasicSipServer::setTlsContext`).
  - Server Name Indication: a certificate per host name (`addHostContext`).
  - `sips:` requests must arrive over TLS (416 otherwise).
  - On Windows, the system's Trusted Root store is used for verification.
- **Virtual hosts** (`CHttpServer::AddVirtualHost`): separate handler factories per host name, including `*.example.com` patterns.
  - HTTPS requests whose host isn't the TLS host name get 421 Misdirected Request.
  - Requests carry how they arrived: `isSecureConnection()`, `getTlsServerName()` and `getHostName()`.
- **Blockchain:**
  - Blocks with binary entries committed by a Merkle root, and a fixed 100-byte header.
  - Full chain validation that reports which block fails and why, with the required difficulty set by the reader.
  - Mining that can be limited, cancelled or done on another thread.
  - Thread-safe chains.
  - Saving to and loading from JSON and binary.
  - `CMerkleTree`: RFC 6962 hashing with inclusion proofs and RFC 9162 verification.
- **SHA-256:** binary `Digest()`, `ToHex()`/`FromHex()`, and `updateData()` for inputs of any length. `StringDigest()` now takes a `const CString &`, so it also accepts temporaries.
- **Sockets:**
  - `ReadWithTimeout()`, `Accept( timeout )` and `Shutdown()`.
  - Waiting that works on every platform (`poll`, or `WSAPoll` on Windows).
  - `ReleaseHandle()`.
  - `IsSecure()` and `GetTlsServerName()`.
- **`BaseTypes/Platform.h`:** the operating system headers in the right order for each platform. **`Threading/ThreadPlatform.h`:** pthreads chosen from the platform flag alone.
- **Tests:** `TestSip`, `TestHttp`, `TestDate`, `TestJson`, `TestTls` and `TestBlockchain`, all run by `ctest`.
- **Docs:** this changelog, and a README with build, usage and testing sections.

### Fixed

- **`CDate`:**
  - **Calendar arithmetic:** across the Julian/Gregorian change and for BC years.
  - **Parsing:** formats that failed or read stale values.
  - **Time zone and timestamp conversions.**
  - **Julian Day on Windows:** a 32-bit overflow made it wrong for every modern date there.
  - **Before AD 1:** the last second of each day was placed in the next day.
  - **macOS:** the C library gave wrong offsets before 1900.
  - **Repeated hours:** the hour that happens twice when the clocks go back was resolved wrongly in zones east of UTC.
  - **Windows parsing:** every date pattern had a copy using `sscanf_s` without its buffer sizes. All 124 copies are gone.
- **Threading:**
  - Data races in `CThread` and `CMutex`.
  - macOS had no threading at all, because pthreads were only chosen for Linux.
  - `CSemaphore` used unnamed POSIX semaphores, which macOS doesn't support, and printed on every construction.
- **Memory:**
  - `CException` copies freed the same memory twice.
  - Copying an empty `CStringArray` leaked.
  - `CString::Pad` and `CIntArray` freed arrays with the wrong form of `delete`.
  - Copying a `CBlockchain` freed every block twice.
- **Sockets:**
  - Timed reads and accepts never timed out on Windows, so servers couldn't stop.
  - `SO_REUSEADDR` let a second server take over a port in use on Windows.
  - `CUDPSocket` didn't link on Windows.
  - Address handling bugs.
- **Structure packing:** `IASLib.h` changed it for every class, so applications and the library laid objects out differently.
- **Blockchain:**
  - Ambiguous hash input let data be changed while keeping the hash.
  - Data after a NUL byte wasn't hashed.
  - The genesis block was never hashed.
  - The difficulty wasn't part of the hash.
- **SHA-256:** messages over 512 MB hashed wrongly (32-bit length counter).
- **Windows C runtime crashes:** `strncpy_s` ended the program when text filled the buffer, and the time functions did the same for dates outside 1970–3000.
- **Unbounded formatting** in exceptions, and string stream truncation.
- **`TestXMLDocument`** crashed in release builds: two test functions never returned a value.

### Removed

- The legacy HTTP classes and `CServer` (see **Breaking changes**).
- `MerkleNode`, `CPojoNode` and `CJsonDocument`.
- The committed `build/` directory, a CMake cache from 2022 that stopped CMake configuring anywhere else. `build/` is now ignored.

### Build and CI

- **CMake:**
  - Threads are enabled properly.
  - SQLite is found with `find_package` (vcpkg on Windows).
  - OpenSSL is looked for on every platform; TLS is built when it's found (`IASLIB_TLS__`).
  - Winsock and `crypt32` are linked on Windows.
  - New `USE_TIMEZONE_ICU` option.
- **GitHub Actions:**
  - One workflow builds and tests on Linux (GCC and Clang), macOS (Apple Clang) and Windows (MSVC), for every push to `master` and `claude/` branches and every pull request.
  - Failed builds list their errors grouped by file, and hung tests time out.
  - It replaces two broken workflows: one used a retired GitHub action, and the other was copied from another project.
  - Pushing a `v*` tag creates a GitHub release, with that version's changelog section as its notes.
- **Sanitizers:** the suites run clean under AddressSanitizer/UndefinedBehaviorSanitizer, ThreadSanitizer and Valgrind.
